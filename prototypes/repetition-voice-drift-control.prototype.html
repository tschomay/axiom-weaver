Prototype — throwaway — answers issue #14 only

Repetition and voice-drift control

Question this demo answers: what an imagery ledger records, how it normalizes "is this the same image", how it tells a licensed motif from lazy repetition, what instruction wording actually produces variation without breaking the voice, and whether scene-shape variety and voice drift need their own mechanisms in #14 or stay where ADR 0002 already put them.

Identical input across every sample below: Cinderella fixture, Voice Card fairy-tale / fable (imagery palette: hearth ash and cinders · gold and silver brocade · glass catching candlelight · garden vermin transfigured into finery), three consecutive house-set scenes — scene_01_remarriage (tone: wistful, quietly bleak), scene_03_dressing_the_sisters (sardonic, needling), scene_04_sisters_depart (lonely). Each excerpt was written by hand against the rendering template below, standing in for the writer call — no live model wiring, same as the prototype/voice-card-style-presets precedent. Excerpts are trimmed for length, not full length_budget.

The ledger, scene by scene

The ledger is built entirely from prior scenes' own imagery_signature digest field (ADR 0003) — no new call, no re-reading prose. Each recorded image is self-tagged by the writer against a Voice Card palette domain at emission time (the one schema change this ticket makes: imagery_signature becomes {image, domain}[], still capped at 3, domain null for an ad hoc image outside the palette).

What we tried and declined: the raw blocklist

Do not use: ash, cinders, grate, soot. These images have already appeared.

Hand-testing this framing against the same three scenes produced prose that avoided hearth imagery entirely rather than varying it — the sisters' hair-dressing scene lost its ash-blackened-fingers detail (a beat-adjacent, characterful image, not filler) and reached for generic substitutes ("her hands moved quickly") that read flatter than the original. A blocklist can't distinguish "don't repeat this phrasing" from "don't touch this domain," so it over-corrects. Declined — see Finding 4.

Findings

1. What gets recorded. Nothing new beyond imagery_signature (ADR 0003), upgraded to carry a domain tag per entry. No verb ledger, no sentence-opener tracking, no sensory-channel field — each would cost digest tokens without independently catching a rubric mode imagery_signature doesn't already cover (ADR 0003's "a field earns its place" test).
2. Normalization. Domain-tag matching, not string or embedding similarity. The writer already has to pick from (or knowingly step outside) the Voice Card's imagery_palette to write the sentence — self-tagging the choice at emission time is free; comparing tags at ledger-build time is a plain equality check, no extra call, consistent with the no-lookup-tool / no-fuzzy-retrieval constraint from #12.
3. Motif vs. repetition. imagery_palette domains already are the motif declaration — "draw from these before inventing new ones" (ADR 0007) licenses a domain to recur across the whole telling on purpose. The ledger constrains reuse of the same vehicle within a domain, never suppresses the domain. Scheduling one specific image (not a whole domain) as a deliberate one-off callback is a real, separate need neither fixture forces — stays fog.
4. The instruction. Positive-framed "already drawn from" list plus an explicit unused-palette nudge, not a "do not use" blocklist — the blocklist over-corrects by suppressing the whole domain (sample above). scene_04's excerpt shows the positive framing doing real work: pulled toward glass catching candlelight (unused so far) for the window-at-dusk beat, landing an image the scene's own content invited (Cinderella catching her reflection) rather than forcing hearth imagery to recur a third time.
5. Voice and ledger don't fight. Register, narrative distance, and sentence rhythm hold across all three "with ledger" excerpts (short declaratives, the plain warmly-ironic narrator) while only the concrete image varies — because the ledger block renders after the Voice Card block and is scoped explicitly to imagery ("vary the vehicle, not the domain"), so it reads as refinement within the voice, never a competing instruction. No wording change to the Voice Card template (ADR 0007) needed.
6. Scene-shape variety — not reopened. ADR 0002 already ruled this "consciously accepted, unaddressed for v1" and explicitly said revisiting it is "new fog, not a reopening of this decision." Nothing in this prototype changes that: variety stays permitted, via the author-set length_budget that already differs per Scene Card (350 / 300 / 200 across these three), never pushed by a new mechanism or digest field. No new field added.
7. Voice drift — not reopened. ADR 0002 is explicit: voice drift is "generation-time only… no post-hoc mechanism catches a drift that already happened." ADR 0007's sketch of anchoring drift-measurement against generated-prose stats (average sentence length, dialogue fraction) is not adopted here as a verification or continuity-pass-flagging step — doing so would quietly reopen ADR 0002's ownership split (voice drift stays outside the continuity pass; the Voice Card carries the full weight). #14's only contribution on this front is Finding 5: confirming the ledger instruction doesn't itself introduce drift by fighting the Voice Card block.
